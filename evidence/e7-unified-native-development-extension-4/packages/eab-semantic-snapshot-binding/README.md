# Stable row IDs do not bind a cache to the right source snapshot

Two authored XLSX workbooks contain the same operation IDs and payload values. Workbook A assigns CLEAR to 12 and KEEP to 13; workbook B swaps those intents. A repacked B reverses input row order and changes unrelated workbook creator metadata. The benchmark reads each actual workbook with native openpyxl, exports OGR Memory Arrow/NumPy integer values and validity, writes actual GeoPackage replacements and checks closed-file SQLite rows by FID. The persisted value oracle derives from the selected workbook action, not the reused sidecar.

The logical Arrow payload is identical for A, B and repacked B. Consequently hashing the canonical projected FID/value list cannot distinguish these snapshots; this is **projection equality**, not a cryptographic collision. Reading B with A's FID-keyed sidecar passes the payload check and writes the wrong persisted values at both stable IDs. Correct B with its own sidecar and repacked B with B's sidecar both preserve the oracle. A literal ZERO control survives all paths.

The useful cache key is an input-authority binding over the scoped semantic patch (operation schema/version plus sorted exact FID, intent and value), not physical payload alone. The selected source or some other trusted authority must supply the expected binding independently of the sidecar offered for reuse. If only Arrow projections remain, no digest derived from them can reconstruct omitted assignment intent. A byte hash of the entire workbook would also distinguish repackagings with no projected semantic change; the scoped semantic key allows this benign reuse. This author fixture assumes unique stable IDs, order-insensitive disjoint one-pass operations and typed payload; it does not apply to repeated/order-dependent actions, general workbook equivalence or untrusted authenticity verification.

Replay with shell pipefail: `python3 -IB producer.py | /usr/bin/python3 -IB check.py | cmp - result.json`.
