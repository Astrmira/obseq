# Exact upper and lower precision-loss witnesses for the workbook numeric writer

R104 showed collisions for particular worksheet numeric values. Here the scoped source domain is **positive normal IEEE-754 binary64** written as an openpyxl 3.1.5 General numeric cell. The pinned writer's numeric formatter uses %.16g. For the model of rounding to 16 significant decimal digits, with ties to even, an exact rational certificate computes the entire preimage of any observed positive numeric token. It also yields a sharp maximum; neither the sample distribution nor reader agreement establishes it.

For the token t in decade k, set q = 10^(k-15). Its immediately higher formatted numeric token is t+q; its predecessor is t−q except at t=10^k, where it is t−q/10. The interval is bounded by the two corresponding exact midpoints. At a tie, t is selected exactly when its significand integer t/q is even; at the lower boundary of a power of ten, t also has even coefficient on the preceding grid. Binary64 bit order is monotone on the admitted domain, so binary search gives the first included and first excluded encoding from those rational endpoints. This uses the exact token, not a parsed binary64 or locale-dependent value.

For non-power tokens, the interval has length q and begins at or above 10^k. All adjacent positive-normal binary64s in it are spaced at least 2^(floor(log2(max(10^k,min_normal)))−52). Across the 617 relevant decades, exact arithmetic verifies q is strictly less than nine of those steps. Therefore no non-power interval can contain ten encodings; exact asymmetric inverse bounds independently check the power tokens. The bound nine is attained: the native workbook writer emits the identical raw token 1.040728623914258e+270 for all nine marked hex inputs. Thus a fixed-width exact source discriminator needs four bits in the worst case; the zero-based rank in the exact preimage interval suffices. This excludes coordinate/type metadata, mitigations for journal corruption, and serialization overhead.

The script validates 5,041 native XML tokens and 25,612 formatter membership/neighbor checks, with a second actual native workbook asserting the nine-way collision. The independent inverse calculations take only rational arithmetic and binary64 integer ordering, not decimal formatting. The sharp bound pertains to the stated rounding model and pinned positive-normal path; it is not a bound for signed integer origins, subnormals, negative zero, numbers modified by formula evaluation, or Excel's GUI. No timing or actual customer workbook claim.
