# Cross-engine join conformance: isolate representation and operator contracts

A versioned benchmark can measure contract preservation and repair precision, not count unrelated bugs. This case fixes the declared relational contract: a bag-preserving inner equijoin over two sets of identified rows, signed int64 keys, and SQL NULL (no match). Oracle output is the set of pairs of immutable source IDs. With unique IDs this still detects both bag losses and fabricated pairs when the keys repeat. Compare exact pairs rather than counts, statuses or formatted values. Row order is immaterial; key type and null semantics are not. This is not a claim that pandas violates its own native contract.

## Native, two-stage witness

`/usr/bin/python3 -IB producer.py | python3 -IB check.py` regenerates result.json. The producer builds real GDAL OGR Memory layers and receives their real Arrow C stream through the NumPy adapter. It verifies all int64 values, row identities, and mask bits as represented by the decoded rows. It serializes the extracted records as decimal integers or null across two Python processes using stdlib JSON (not JavaScript numbers). Separately, SQLite executes the authored join. The SQLite pairs must agree with a direct Python integer/null nested-loop oracle. The consumer varies only two factors after exact parsing: pandas default inference vs nullable Int64 constructed through object storage; and native merge vs independently applied SQL NULL filtering.

The fixture includes ordinary small integers, adjacent keys just beyond the positive and negative exact binary64-integer boundary, and the largest adjacent signed int64 keys. For each there is a paired case with one NULL appended to each table. Existing non-null joins cannot change after such insertion under the declared SQL contract. Every case contains a duplicate key on the left so that set-of-key comparison cannot substitute for output-pair identity. Among the three precision-stress cases, the default null-augmented consumer creates three false non-null matches via binary64 collapse and one false NULL match. Int64 alone removes the former; filtering NULL alone removes the latter; both restore every expected pair across all eight cases. Clean arms remain correct. This separates the two causes without misdiagnosing an intact Arrow export as responsible.

## What would make the benchmark useful beyond this witness?

For every released case declare the typing, null handling, bag/order rules and interoperable subset before comparing engines. Include one fixture transform with a logic-defined invariant (here NULL insertion), one below-threshold control, and one repeated-key control. Score false and missing exact IDs separately, and add the first observed divergence stage by placing sentinels at source, decoded values/masks, post-materialization storage, and final operator. Publish native/default and contract-aligned arms side by side. A typed connector should be allowed to infer correctly; a configurable adapter should be scored separately on effective defaults and repair. On unfamiliar held-out compositions, record whether the same contract declaratively repairs the output rather than patching each witness. Additional consumers, datasets and performance are unmeasured. If measuring cost later, time full parse/materialize/join and include schema/contract metadata under equal correctness; a fast false result is not a speedup.
