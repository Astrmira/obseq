# Repack a shared formula only within an exact translation-equivalent rectangle

The input is an actual two-dimensional shared OOXML group B2:E5. The staged cut model moves A1:B2 to G7:H8 after expanding the old formula instances and retargeting references by identity. The test covers only authored same-sheet scalar A1 expressions with integer arithmetic and original dollar flags; no arbitrary OOXML parser or Excel claim.

**Exact local sharing test.** For each supported formula host, retain its literal/token skeleton and replace every reference axis by either (locked, absolute coordinate) or (unlocked, coordinate minus host coordinate). Preserve the lock flag even if two current addresses happen to match. Equality of these signatures is necessary and sufficient for two formulas to be written as one master plus marked-axis translations in this token grammar, subject to their source being in bounds. For a complete contiguous rectangle with one signature, use its top-left cell as master, emit one ref and unique si, and emit only shared follower markers on every other cell. Different signatures cannot share under this contract in either direction. Identical signatures do not make noncontiguous or holed cells into a valid group in this writer.

**A safe grouping algorithm, not an optimization claim.** Sort existing formula hosts by row and column, build maximal homogeneous horizontal runs, and merge runs of identical endpoints/signature across consecutive rows. This disjoint cover preserves every host and emits valid rectangular groups. It does not claim minimum #groups or maximum ZIP savings; sorting sparse coordinates avoids enumerating the whole worksheet. For the authored cut it emits D2:E3, B3:C3, B4:C5 and D4:E5, while C2 and moved H8 stay ordinary. Thus six formula texts suffice for the sixteen cells (four masters and two singletons), without a claim about compressed bytes. Independent raw XML verifies the exact rectangular membership and re-expands the groups by direct master deltas; reopened openpyxl agrees.

**Small negative witness.** For adjacent C2/D2, the expected C2 formula refers to H7 and H$7, while desired D2 refers to C1 and C$1. A two-cell shared group is structurally contiguous, but translating the C2 master yields I7 and I$7 for D2 instead. The intentionally wrong repack alters only D2's expanded formula and causes a separate value change at its dependent E3. This distinguishes structural validity from formula-identity preservation at the minimum two-host sharing size.

LibreOfficeDev 26.8.0.0.alpha0 independently consumed and recalculated the staged expanded, safely repacked, and intentionally mis-merged sheets. All sixteen cached values match the independent exact integer oracle on the safe arms; the invalid arm yields the independently predicted two affected values. This is native shared-formula consumption/recalculation, not native cut/copy, clipboard or Excel execution. The source workbook remains byte-identical. Unsupported: named/cross-sheet/range/array or dynamic refs, arbitrary expression normalization, overlapping/partial shared-group admission, malformed workbook recovery and globally optimal rectangle packing.

Replay exact writer/reader checks: `python3 -IB check.py | cmp - result.json`. Native calculation: `python3 -IB check.py --consumer | cmp - consumer.json`.
