# Date formatting can make a numeric workbook roundtrip non-injective

**Contract:** unmodified signed-off workbook numerics and their calculation semantics must be preserved, even when a numeric cell is formatted for display as a date. Compare raw worksheet XML values, parsed Python date objects, and (separately) cached outputs after a native recalculation. The workbook contains adjacent serials across the 1900 compatibility discontinuity, numeric twins with General style, and a second workbook using the 1904 date system.

On openpyxl 3.1.5, loading date-styled serial 59 and 60 in the 1900 date system produces the same Python datetime (1900-02-28). The same alias occurs for 59.5 and 60.5 at noon. Saving without edits changes 60 to 59 and 60.5 to 59.5, while preserving the others. General numeric twins and 1904-system controls preserve every serialized value. This is loss of stored numeric identity, not evidence about the Excel GUI's representation of the dates.

For exact half-day values in the authored range, at each ambiguous datetime there are exactly two possible inputs. An independent bit identifying the upper preimage is necessary in the worst case and sufficient when attached to the changed-cell location. The script captures marked cell coordinates before load and restores one day only on those cells after save, verifying exact serialized numerics. A coordinate list encodes position as well; it does not cost literally one file bit per cell. This is a microfixture for non-injectivity, not a general XLSX repair tool. Rich worksheet parts, different precision/time formats, style changes, shifted coordinates, and arbitrary ZIP transformations are outside the bit claim.

Replay `python3 -IB check.py | cmp - result.json`.

**Independent consumer check:** `python3 -IB check.py --consumer` (optional) uses LibreOfficeDev 26.8.0.0.alpha0, build 2c87e51eeaa2b413ff4ae097b2705eea1995d8e5, to recalculate and export four workbooks. Formula C is defined as the date-styled numeric A minus the initially identical General numeric B. Raw cached differences are zero in both original workbooks and the 1904 roundtrip. Only at the two aliased 1900-system cells do the roundtripped values produce -1, directly demonstrating a downstream computation change. The repair assertions check serialized values, not the repair's native recalculation. No Microsoft Excel executable was run.
