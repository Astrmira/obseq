# E9 collection: interpretation boundaries
The five-year window indexes ticket creation, not the date of a confirmed defect or fix. This is a query-enriched, truncated convenience frame; report only within-sample evidence, not project prevalence. Different trackers index differently. GitHub and openpyxl use oldest-first first page per query; SQLite's public Fossil search exposes relevance-ranked post snippets, not equivalent pagination or ticket lifecycle. Only first-page forum thread starters with term in title and in-window source dates qualify; replies/edits are not independent cases. Forum search has no native fix status. SQLite safety screening is title/snippet only, not complete thread text. openpyxl additionally rechecks title substring. Accordingly recompute sensitivity omitting forum and by tracker. Tokenization and API search ordering are provider-defined. Dedupe is URL-based, not root-cause based: cross-ticket duplicates must be linked in adjudication. Trackers' closed status alone is not a verified fix. Public bodies and user handles are not saved. For reproduction, keep generated packets and source hashes since live search ranking and edits drift.
