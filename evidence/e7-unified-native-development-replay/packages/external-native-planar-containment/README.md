# External-artifact admission: exact planar component containment

This is a **new** predeclared operator, not an extension of the authored integer-rectangle overlap oracle. It reads the installed pinned QGIS world map artifact read-only and retains the earlier mechanically selected 12-row countries cohort. Before running the new comparison, policy.json froze the eligible component grammar and deterministic probes. Select the first individually eligible no-hole polygon component from each supported row; never silently promote a component result to a whole MultiPolygon result. Unsupported FID 8 is recorded unchanged.

The independent reference parses raw SQLite geometry blobs directly and converts stored binary64 vertices and query points to exact dyadic rationals. For one ring it checks unique vertices, nonzero exact signed shoelace sum, noncollinear adjacent edges, and exact absence of nonadjacent segment intersections. The parity oracle first returns boundary only on exact zero orientation and segment inclusion. Otherwise it uses a half-open horizontal crossing test: count an edge iff its endpoints straddle the query's ordinate and its crossing lies strictly to the right. The sign of orientation relative to edge direction decides the latter without computing a rounded intersection. For the admitted simple ring, odd parity is interior. Native GDAL fetches the same feature by stable FID; exact ring coordinates verify component alignment independently of native containment.

Actual comparison: 11 admitted components, 1,245 distinct per-component query probes, 545 interior, 165 exact boundary and 535 exterior. Native GEOS Contains accepts only interior; Intersects additionally accepts boundary. Both agree with the exact oracle on all probes, including represented exact edge midpoints and one-ULP neighbors of vertices. This is a scoped positive transfer on a real external artifact, not “GEOS proved correct,” a representative sample, a blind review, or evidence for the rejected area operator. The coordinates are treated only as planar x/y; there is no CRS transformation, geodesic interpretation, area prediction, hole/multipolygon-union test or performance claim. The unsupported feature is not decoded by extending the parser.

Replay on this installed artifact: `/usr/bin/python3 -IB check.py | cmp - result.json`.
