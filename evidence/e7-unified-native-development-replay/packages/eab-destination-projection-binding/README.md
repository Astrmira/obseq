# Source provenance alone does not bind a cached write outcome

The earlier workbook/Arrow fixture shows stale operation intent can pass a payload-only source check. This complementary replay fixes every source field and operation and changes only the destination's before-state. The contract is to reuse an *exact post-state receipt*, not merely to run the same commands on whatever state exists now.

Within a closed identity/column set, no triggers or preconditions, and independent unconditional replacement, CLEAR and WRITE set constants while KEEP is identity. Then two before-states produce exactly the same scoped post-state iff all preserved coordinates agree: (i) exact row existence/identity, (ii) cells on which the action is KEEP and (iii) untouched columns. The proof is coordinatewise: overwritten cells always match, preserved cells match iff they already match. A changed overwrite target alone is not a reason to invalidate this post-state receipt. Conversely checking only edited columns is insufficient when the receipt asserts protected values. These conditions concern receipt values; operation acceptance/errors and audit trails remain separate observations.

The checker replays actual GDAL GeoPackage writes and queries closed-file SQLite by stable FID. Changing only overwritten target values (including a real NULL) preserves the baseline post-state even though a whole-before-state hash changes. Changing the KEEP value or an untouched control column independently changes the post-state while the source patch is still identical. A preservation-specific digest distinguishes the latter without rejecting the first. Independent un-hashed equality checks establish the observed values; a digest is a compact comparison only with its usual assumptions. The independent modeled patch oracle also checks all three action kinds in 3,645 authored comparisons.

Suggested reusable suite routing: first compare authoritative source-operation binding; then bind the destination identity and preservation projection for exact receipt reuse; next check operation status and actual closed-store rows. For trigger, conditional-write, compare-and-swap, or concurrent targets the before-state dependency is larger and must be analyzed separately. This is not atomic admission across independent resources and does not claim such security or backend-wide applicability.

Replay: `/usr/bin/python3 -IB check.py | cmp - result.json`.
