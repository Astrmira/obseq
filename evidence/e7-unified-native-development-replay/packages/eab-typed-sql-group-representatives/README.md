# Group identity can be deterministic while its physical representative is not

The relational benchmark pins a closed eligibility universe of strict SQLite ANY inputs: NULL, finite REAL, signed INTEGER, BINARY text and BLOB. The independent Python oracle treats finite REAL and INTEGER with the same exact value as one numeric group (exact rationals), keeps the other storage classes separate, and counts input multiplicity. The contract then distinguishes quotient correctness, physical representation, and a stronger canonical eligible representative. It does not require that every plan select the same otherwise-allowed representative.

In actual SQLite repeated 1.0 and 1 form one numeric group and repeated NULLs another. Text '1' and the single-byte BLOB are separate. Two forced covering-index scans return different SQLite DISTINCT representations: INTEGER 1 in forward order, REAL 1.0 in reverse order. The quotient classes and GROUP BY input counts match the independent oracle in both plans. Materializing the representatives in a STRICT ANY destination preserves this difference, so downstream typeof() counts genuinely differ. Comparing only the serialized values or group counts would conflate different contracts. If the physical recipient requires deterministic provenance, ROW_NUMBER PARTITION BY x ORDER BY seq chooses the same minimum stable ID and exact storage class in both native plans. The output presentation order is immaterial.

The same test crosses 96 seeded authored inputs, including 2^53 neighbors, signed numeric equality, empty text/BLOB and duplicate NULL. Fifty-one of 96 show differing physical type histograms despite valid outputs for the quotient contract. The taxonomy is executable: exact group membership and multiplicity are mandatory, a physical representative belongs to the allowed type/value set of that group, and canonical minimum-ID selection is a separate stronger gate. This contrasts with R120's shared top-k witnesses: here the quotient group and count themselves are stable, and representation may still alter a downstream typed observable. This does not quantify production prevalence or generalize to affinities, collations, NaNs, other engines, or performance.
