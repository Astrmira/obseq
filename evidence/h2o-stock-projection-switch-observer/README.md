# EA&B: a Q3 partner-swap detector using only stock projected values

The previous occurrence-ordinal detector needed an instrumented left/right replay. Here, a different exact bounded fault detector consumes the original 11 projected Q3 columns, without hidden row ordinals. It catches a single nontrivial exchange of admitted projected rows, even when a chosen visible ID field is useless. This is not full bag equality and does not certify true source occurrence identity for duplicate projected rows.

Choose injective codes L and R for the left and right output blocks, each less than a prime p. Record sum(L*R) modulo p. Before and after swapping two right blocks, the change is (L1−L2)(R2−R1). It is nonzero exactly when both block pairs are different, the same condition for that exchange to change the projected two-row bag. Duplicate indistinguishable blocks cannot make this particular exchange change the declared bag. Unlike per-side counts, histograms, sums or moments, one mixed moment sees the association. A separately chosen pair with both left id3 NULLs illustrates why merely picking one named field as L does not suffice.

The reference follows established [factorized aggregation](https://arxiv.org/abs/1307.0441): sum left codes in each join-key group and multiply by the right code (or the sum of right codes if the key has multiple right rows). Under the certified H2O Q3 shape, medium keys are unique, absent right blocks use the all-NULL code zero, and left NULL never matches. The reference does not enumerate the expected join pairs. The candidate still needs to be read. Stock Q3's SELECT body is extracted from the unchanged [pinned upstream source](https://github.com/duckdblabs/db-benchmark/blob/3b074bc3190468803b3a890301f87ce455114d20/duckdb/join-duckdb.py), retaining its original logical projection and DOUBLE/ENUM source types, using the previous streaming CSV materialization. Carrying a witness-styled SELECT that adds ordinals is not necessary.

The generated corpus is exact finite six-decimal data. For this contract, only admitted binary64 values equal to the canonical cast of their six-decimal values are accepted. NULL gets a disjoint code. The three left string ID renderings and one right rendering are proved redundant on every source row, and are explicitly checked again on every native candidate value before omission from the code. The remaining right string ID has its exact canonical numeric suffix checked. Bounded mixed radix makes the packed blocks injective: neither shared digits nor an arbitrary hash can serve as that proof. 128-bit native multiplication and the 89-bit prime cannot overflow on this admitted domain; the unsigned residues also sum within signed 128 bits. NaN, arbitrary submicro-unit floats, noncanonical strings and unsupported types are not accepted. Exact float bit-pattern equivalence is not the contract.

Clean native projection, full right block switch, and value-only (v2) switch share the same original cohort and pinned source. All 10,000,000 native projected rows satisfy the admission predicates and the clean mixed moment equals the independent Python result. Both witness left codes occur exactly once, and both stock id3 values are NULL. The v2-only switch preserves exact projected v2 sum and does not change the other right fields, so detecting it is not just a right-ID/join-key consistency check. A 3-by-2 signed contrast shows larger balanced changes can preserve the mixed moment; do not infer a general collision guarantee. Exact typed bag comparison remains the general answer for already admitted data, and its own pre-coercion representation must be verified separately.

Run `python3 -B run.py DATA_DIR PINNED_JOIN_DUCKDB_PY` and compare to RESULT.json using DuckDB 1.4.3. No source rows, external I/O timing, benchmark speed, or error prevalence claim.
