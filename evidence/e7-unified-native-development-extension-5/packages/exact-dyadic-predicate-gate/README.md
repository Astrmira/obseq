# EA&B dyadic point predicate gate: exact transform, certified sign, exact fallback

This follows the independently admitted whole-MultiPolygon probe where native whole and native components agreed with each other but missed strict Contains at the smallest positive binary64 displacement above a valid T-contact. It does not infer GEOS's internal operation or change the planar validity scope.

## Exact coordinate transform is a representation theorem, not a native sign certificate

For one fixed positive scale λ=2^k, admit the same transform for all stored coordinates and queries only if every transformed binary64 is finite, its inverse gives the identical binary64 bit pattern, and its exact dyadic value equals λ times the original. The last test is checked as a rational equality; do not mistake round-trip success for an arbitrary affine transform's correctness. Then coordinate order and equality are preserved, and exact orientation determinants are multiplied by λ². Thus exact on-segment tests, half-open ray parity, shell/hole and component admission, and point membership are unchanged. Do not rescale only a query or one ring and call that the same input.

This does **not** guarantee that all arithmetic products or determinants computed on the transformed binary64 values are representable. Let η=2^−1074. The orientation of (0,0),(η,0),(0,η) is strictly positive; transforming coordinates by 2^20 is admitted exactly, yet its nominal floating product still rounds to zero. For this product to be representable without underflow needs k≥537. A receipt also containing 2^1023 cannot admit any positive integer k because the large coordinate overflows; an exact scale down loses η. So there is no nonzero conservative global lift on that mixed-exponent receipt. This last example is an arithmetic obstruction, not an asserted valid external geometry or a native error report.

## Certified guard for ambiguous point/edge pairs

Use finite stored binary64 endpoints as singleton intervals. For every difference, product and final subtraction in the orientation determinant, calculate extreme rounded bounds and widen one adjacent binary64 toward negative/positive infinity respectively. This encloses true values under ordinary correctly rounded binary64 arithmetic with gradual underflow and no algebraic reassociation. If a bound or widening overflows, or the final interval meets zero, compute the exact dyadic orientation. Identical endpoints or all equal axis coordinates give an immediate structural zero. The sign is independently certified only if the final interval is strictly positive or negative; there is no epsilon classification. Exact binary64 comparisons do axis range and half-open ray gating. Boundary needs orientation zero plus the bounding-box check; crossing parity uses the certified orientation sign. A platform that does not satisfy the floating arithmetic premises must use only the exact branch. Existing validity admission is still required; exact point predicates on an invalid multipart seam are not a validity repair.
