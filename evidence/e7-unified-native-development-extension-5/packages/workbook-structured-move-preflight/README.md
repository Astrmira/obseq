# Moving a workbook array or data-table footprint is not an atomic edit

The contract here is structural, not recalculation: an anchored array formula or 2D data-table formula declares one rectangular output group. Moving the whole group to blank disjoint space must move its anchor and every member, translate the declared output ref as a group, and preserve references to external inputs not selected for movement. Compare actual worksheet XML formula anchor, type, ref, formula text/attributes and occupied member coordinates.

On openpyxl 3.1.5, whole-group move_range with translate=False moves coordinates but leaves the declared ref at the old C1:D3. With translate=True both object types raise TypeError. The operation is not atomic for this fixture: after the exception the anchor and four other output cells have moved, while D1 remains behind. Saving this partially changed worksheet produces a ZIP with the observed stranded declaration; an exception handler must not assume the workbook is unchanged. The successful structural control pre-admits the complete group, performs the non-translation move, then changes only its output ref to F6:G8; array input formula text and data-table r1/r2 remain anchored to the old input cells. In a real editor, edit a disposable copy and verify before replacing the original.

A native anchor-only move generates a nonrectangular footprint: one point at F6 and the rest of C1:D3 in place. Any rectangle containing the moved anchor and retained member cells must contain intervening untouched cells. Therefore this cut cannot be repaired by changing only a single declared rectangular ref under the stated exact footprint contract. Reject it before mutation or redesign the operation; this result does not rule out a new layout or explicitly different formula semantics. Real caches, spill computation, compatibility with Microsoft Excel and consumer recalculation are untested.
