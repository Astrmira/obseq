# EA&B: forward-only transfer of source edge membership

Use authored straight longitude/latitude segments and exact rational source-edge parameters. Traditional GIS axis order, WGS84 EPSG:4326 to EPSG:3857, continuous longitude branch, no dateline, no singular latitude, not geodesics. Transform a two-vertex chord, a source-subdivided polyline, and each independent source query point using GDAL/PROJ; each representation goes through ISO WKB write/read. Check native GEOS-backed Intersects and independently exact rational orientation + closed-segment between-ness over the stored binary64 coordinates. This is distinct from forward-then-inverse coordinate round trip.

The [PROJ Web Mercator definition](https://proj.org/en/stable/operations/projections/webmerc.html#mathematical-definition) gives x=Rλ, y=R asinh(tan φ). The latter's second derivative divided by R is sec(φ)tan(φ). Therefore northern nonvertical oblique segment images lie strictly below their projected endpoint chords, southern images strictly above. Horizontal/vertical images preserve membership; a symmetric equator straddle admits its exact midpoint, not arbitrary off-midpoint membership. For each uniform subdivision, the analytic real-arithmetic paired geometric error is bounded by R max|sec(φ)tan(φ)| h²/8, h latitude span per subdivision. Use power-of-two subdivisions chosen until the evaluated analytic bound is under 100 m; this evaluated value is not a certified native transcendental implementation error. [GDAL already documents source-space segmentization before reprojection](https://gdal.org/en/stable/programs/ogr2ogr.html#cmdoption-ogr2ogr-segmentize); curvature/densification are not claimed novel. This adapter authors dyadic splits to give exact source parameters rather than depend on option-specific vertex placement.

For the northern control (−5°,10°)→(5°,30°), source midpoint intersects the source edge but is **38,188.98 m below** the projected endpoint chord. It intersects the densified stored polyline because its known parameter is a retained vertex. Nearby source parameter 33/64 is not a retained vertex: after 32 subsegments, it remains **37.45 m below** the local densified chord and still fails exact represented-boundary qualification despite satisfying the geometric tolerance. Mirrored south and a separate held-out northern edge confirm sign/density behavior. Six fixtures × four queries × three represented geometries = 72 exact/native predicate agreements; exact representations disagree across contracts, not across in-representation predicates.

**Admission split:** report source-edge membership (via immutable edge identity and source parameter), exact stored-target membership, and any tolerance-based approximate transfer as three separate results. A geometric error bound doesn't convert near-boundary into exact boundary. A separate conditional side certificate is possible from independent certified boxes for the six target coordinates: the orientation determinant is multi-affine, hence extrema over the box occur among the 64 corners. Strict sign certifies side, while 0 in the range is generally unresolved (membership also needs between-ness and non-degeneracy). The script tests an expressly hypothetical ±1 cm box around native outputs, not a PROJ accuracy claim. Shared or structured errors can require a different joint uncertainty model. Neither these authored native signs nor the analytic curve formula explain round-trip bit drift; no forward-inverse experiment was run for this packet.
